# Установка Agent Second Brain: пошаговая инструкция

Эта инструкция ведёт от аренды сервера до работающего агента в Telegram с
личной памятью. Рассчитана на человека, который уверенно пользуется
компьютером, но никогда не арендовал сервер и не работал в терминале.
Каждую команду копируйте целиком.

У каждой команды три подсказки:

* **Результат**: что вы увидите, если всё хорошо;
* **Проверка**: как убедиться, что шаг сделан;
* **Если ошибка**: что делать, если что-то пошло не так.

Время: около полутора часов: аренда сервера 20–40 минут (в основном ожидание, пока провайдер его создаст), установка около часа, из них 15–25 минут ожидания.

**Что понадобится во время установки, кроме терминала.** Установщик нельзя
пройти «одной командой» без вас: три раза нужно действие на компьютере или
телефоне, все три описаны в разделе 7: вход в GitHub по коду (шаг 5
установщика), нажать **Start** в своём боте и вход в ChatGPT или Claude по
ссылке и коду. Коды действуют 15 минут. Если не успели, просто запустите
установку снова.

## 1. Что получится

На вашем сервере круглосуточно работают:

* **Telegram-бот**: вы пишете или говорите голосом, агент отвечает;
* **агент** на Codex (подписка ChatGPT) или Claude Code (подписка Claude): читает и пишет файлы, ставит напоминания, разбирает заметки;
* **память (vault)**: обычные markdown-файлы, которые открываются в Obsidian;
* **резервная копия памяти** в вашем приватном репозитории GitHub;
* **расписания**: ежедневная обработка записей в 21:00, проверка здоровья в 08:00 и ваши собственные напоминания.

Есть два разных репозитория:

| Репозиторий | Что внутри | Доступ |
|---|---|---|
| [`agent_second_brain_upgraded`](https://github.com/parnyakov/agent_second_brain_upgraded) (на сервере папка `~/projects/agent-second-brain`) | программа и пустые шаблоны, без чьих-либо личных данных | публичный: скачивается без входа, приглашения и форка |
| `dbrain-vault` в вашем аккаунте GitHub | ваша память: цели, заметки, проекты | только вы: установщик создаёт его строго PRIVATE |

Программу вы только скачиваете на сервер. Форк (своя копия на GitHub) не
нужен, кнопку **Fork** не нажимайте. Всё личное хранится во втором,
приватном репозитории, который видите только вы.

## 2. Подготовка аккаунтов

Сделайте это на компьютере или телефоне до подключения к серверу. Секреты
пока сохраните в заметке на своём компьютере; после установки эту заметку
удалите.

### 2.1. GitHub

Зарегистрируйтесь на [github.com](https://github.com), если аккаунта нет,
и запомните логин и пароль.

Аккаунт нужен только для вашей памяти: на шаге 5 установщик попросит войти в
GitHub и создаст в вашем аккаунте приватный репозиторий `dbrain-vault`.
Для скачивания программы вход не нужен: она лежит в открытом репозитории
<https://github.com/parnyakov/agent_second_brain_upgraded>.
Приглашение и форк не нужны.

**Проверка**: вы входите на github.com своим логином, а страница программы
открывается в браузере даже без входа.

### 2.2. Telegram-бот

1. В Telegram откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Придумайте отображаемое имя, затем имя пользователя бота, которое заканчивается на `bot`.
3. BotFather пришлёт **токен** вида `1234567890:AAH...`. Это пароль бота, никому его не показывайте.

**Проверка**: в сообщении BotFather есть строка `Use this token to access the HTTP API`.
**Если ошибка**: имя занято. Придумайте другое имя, заканчивающееся на `bot`.

### 2.3. Ваш Telegram ID

Откройте [@userinfobot](https://t.me/userinfobot) и нажмите **Start**. Он
пришлёт число `Id: 123456789`. Бот будет отвечать только этому ID.

### 2.4. Deepgram (расшифровка голосовых)

1. Зарегистрируйтесь на [console.deepgram.com](https://console.deepgram.com). Бесплатного стартового кредита хватает надолго.
2. Откройте **API Keys → Create a New API Key**, права **Member**, срок без ограничения.
3. Скопируйте ключ сразу: второй раз его не покажут.

### 2.5. Подписка для «мозга» агента

Нужна одна из двух:

* **ChatGPT Plus или Pro** для Codex (рекомендуем для первого запуска);
* **Claude Pro или Max** для Claude Code.

API-ключи не нужны: агент работает через вашу подписку.

## 3. Аренда сервера

**Что такое сервер (VPS) и зачем он нужен.** VPS — это компьютер в
дата-центре, который вы берёте в аренду помесячно. Он включён круглосуточно,
поэтому агент отвечает вам, даже когда ваш ноутбук выключен. Экрана и мыши у
него нет: им управляют двумя способами:

* **панель провайдера** на сайте, где вы арендовали сервер: оплата,
  включить/выключить/перезагрузить, сбросить пароль, переустановить систему,
  аварийная консоль в браузере;
* **SSH** из терминала на вашем компьютере: текстовое окно, в которое вы
  вставляете команды, а выполняются они на сервере (раздел 4). Вся установка
  идёт через SSH.

### 3.1. Какой сервер нужен

| Параметр | Что выбрать | Почему |
|---|---|---|
| Операционная система (ОС) | **Ubuntu 24.04 LTS**, 64-bit (x86_64 / amd64) | на ней установщик проверен. Не выбирайте Windows, CentOS, «Ubuntu с панелью», Docker-образы и готовые приложения: нужна чистая Ubuntu |
| Процессор | **2 vCPU** | |
| Память | **4 ГБ RAM** (минимум 2 ГБ) | агент, бот и сборка при обновлении одновременно занимают около 2 ГБ |
| Диск | **от 40 ГБ SSD** (минимум 30 ГБ) | программа, память, логи и запас на обновления |
| Расположение | **Европа, например Нидерланды** | ChatGPT (Codex) и Claude не работают с серверов в России и Беларуси: вход в подписку не пройдёт |
| Тип | обычный VPS, **только под агента** | агент получает на этом сервере широкие права (раздел 12), других сайтов и программ там быть не должно |
| Доступ | вход **root по паролю** | так проще всего начать; ключ SSH можно не загружать |

Этого хватает с запасом для одного человека. Добавить ресурсы позже можно в
панели провайдера без переустановки.

### 3.2. Где арендовать

Подойдёт любой провайдер VPS с серверами в Европе. Мы используем
**[HOSTKEY](https://hostkey.ru/vps/)**, локация **Амстердам, Нидерланды**: он
принимает российские карты, панель на русском, сервер готов примерно за 15
минут. Дальше шаги описаны на его примере, у других провайдеров они такие же
по смыслу.

1. Зарегистрируйтесь на сайте провайдера и подтвердите почту.
2. В разделе **VPS / виртуальные серверы** выберите локацию **Нидерланды**.
3. Выберите тариф не меньше **2 vCPU / 4 ГБ RAM / 40 ГБ диска** (таблица
   выше). Самые маленькие тарифы с 1 ГБ памяти не подойдут.
4. В поле **операционная система** выберите **Ubuntu 24.04** (не «22.04»,
   не «Desktop», без дополнительных программ и панелей вроде ISPmanager).
5. Если предлагают указать имя сервера (hostname), напишите любое латиницей,
   например `agent`. SSH-ключ можно не добавлять.
6. Оплатите. Помесячной оплаты достаточно.
7. Дождитесь письма «сервер готов» (обычно 5–30 минут). В письме и в панели
   провайдера будут три вещи, сохраните их в заметку:
   * **IP-адрес**, четыре числа через точку, например `203.0.113.25`;
   * **логин**: `root`;
   * **пароль root**.

**Проверка**: в панели провайдера сервер в статусе **Running / Активен /
Включён**, указана ОС Ubuntu 24.04.
**Если ошибка**:

* Письма нет больше часа: проверьте папку «Спам» и раздел серверов в панели,
  пароль root часто виден там же (кнопка «показать пароль» или «данные
  доступа»). Если его нет, напишите в поддержку провайдера.
* Случайно выбрали не ту ОС: в панели есть **переустановка ОС**
  (reinstall). Выберите Ubuntu 24.04. Сервер будет стёрт, пароль root
  придёт новый.

### 3.3. Что пригодится в панели провайдера

Запомните, где в панели находятся эти кнопки, они выручат, если что-то
пойдёт не так:

| Кнопка в панели | Когда нужна |
|---|---|
| **Перезагрузка** (Reboot) | сервер не отвечает по SSH и бот молчит |
| **Сброс пароля root** | забыли пароль root |
| **Консоль** (VNC / KVM / «консоль в браузере») | SSH не пускает, а войти очень нужно: это экран сервера прямо в браузере |
| **Переустановка ОС** (Reinstall) | начать с чистого листа. Стирает всё на сервере; ваша память при этом цела в приватном GitHub (раздел 15) |
| **Оплата / продление** | сервер отключают, если закончилась оплата, и агент перестаёт отвечать |

## 4. Первый вход по SSH

SSH уже встроен в Windows 10/11 и macOS, ничего устанавливать не нужно.

**1. Откройте терминал на своём компьютере:**

* **Windows**: нажмите **Пуск**, напечатайте `PowerShell`, откройте
  «Windows PowerShell». Откроется синее или чёрное окно с текстом.
* **macOS**: нажмите `Cmd + Пробел`, напечатайте `Терминал` (или
  `Terminal`), нажмите Enter.

**2. Вставьте команду**, заменив `IP_СЕРВЕРА` на ваш IP из письма (без
пробелов, например `ssh root@203.0.113.25`), и нажмите Enter:

```bash
ssh root@IP_СЕРВЕРА
```

Как вставлять текст в терминал: в Windows PowerShell — **правая кнопка
мыши** или `Ctrl+V`; в macOS — `Cmd+V`.

**3. Подтвердите сервер.** При первом входе появится вопрос
`Are you sure you want to continue connecting (yes/no/[fingerprint])?`.
Напечатайте `yes` целиком и нажмите Enter.

**4. Введите пароль root** из письма и нажмите Enter. **Символы пароля при
вводе не отображаются совсем**, даже звёздочками: это нормально, терминал не
завис. Пароль удобно вставить (правая кнопка мыши / `Cmd+V`) и нажать Enter.

**Результат**: приветствие Ubuntu и строка вида `root@agent:~#`. Всё, что вы
теперь печатаете в этом окне, выполняется на сервере.
**Проверка**: команда `whoami` выводит `root`, а `lsb_release -d` выводит
`Ubuntu 24.04...`.
**Если ошибка**:

* `Connection timed out` или долго ничего не происходит: неверный IP или
  сервер ещё создаётся. Проверьте IP в панели и подождите пару минут.
* `Connection refused`: сервер ещё загружается. Подождите 2–3 минуты.
* `Permission denied, please try again`: неверный пароль. Вставьте его
  заново; не получается — сбросьте пароль root в панели провайдера.
* `REMOTE HOST IDENTIFICATION HAS CHANGED`: вы переустановили сервер с тем же
  IP. Выполните на своём компьютере `ssh-keygen -R IP_СЕРВЕРА` и повторите вход.
* Сразу после входа просят сменить пароль (`You are required to change your
  password`): введите текущий пароль, затем дважды новый и запомните его.

**Как выйти и зайти снова.** Команда `exit` закрывает подключение (сам
сервер и агент продолжают работать). Закрыть окно терминала тоже безопасно.
Зайти снова — той же командой `ssh`. Чтобы не набирать команду, в терминале
можно нажать стрелку **вверх**: появится предыдущая команда.

## 5. Рабочий пользователь

Агент не работает от root, установщик от root запускаться откажется.
Создайте обычного пользователя с именем `user`. Дальше в инструкции везде
используется это имя. Можно выбрать и другое короткое имя латиницей
маленькими буквами; тогда подставляйте его везде вместо `user`.

Выполните под root (строка заканчивается на `#`):

```bash
adduser user
```

**Результат**: два раза `New password:` / `Retype new password:`. Придумайте
пароль пользователя user, введите его дважды (символы не видны) и
**запишите**: он понадобится на шаге установки и каждый раз, когда сервер
спросит `[sudo] password for user:`. Затем вопросы `Full Name`, `Room Number`
и другие: на все нажимайте Enter, в конце на `Is the information correct?`
ответьте `Y`.

```bash
usermod -aG sudo user
```

**Результат**: команда ничего не выводит, это и есть успех.
**Проверка**: `groups user` показывает строку со словом `sudo`, например
`user : user sudo users`.

Выйдите и войдите уже новым пользователем:

```bash
exit
```

```bash
ssh user@IP_СЕРВЕРА
```

Пароль теперь вводите тот, что придумали для user, а не пароль root.

**Результат**: строка вида `user@agent:~$` (знак `$`, а не `#`).
**Проверка**: `sudo -v` спрашивает пароль пользователя user и ничего не пишет после ввода.
**Если ошибка**: `user is not in the sudoers file`. Войдите снова как root и
повторите `usermod -aG sudo user`.

С этого момента на сервер всегда входите как `ssh user@IP_СЕРВЕРА`. Вход
как root нужен только в редких аварийных случаях.

## 6. Одна команда запуска

Скопируйте команду целиком, ничего в ней не меняя, и выполните её под
пользователем `user`:

```bash
sudo apt-get update && sudo apt-get install -y git curl && git clone https://github.com/parnyakov/agent_second_brain_upgraded.git ~/projects/agent-second-brain && bash ~/projects/agent-second-brain/bootstrap.sh
```

Что происходит по порядку:

1. `sudo apt-get ...` ставит `git` и `curl` (если они уже есть, apt так и
   напишет). Сразу появится `[sudo] password for user:`: введите пароль
   пользователя user из раздела 5 и нажмите Enter. Символы не видны, это
   нормально.
2. `git clone ...` скачивает программу из открытого репозитория в папку
   `~/projects/agent-second-brain`. Логин GitHub здесь не нужен и не
   спрашивается.
3. `bootstrap.sh` запускает установщик. Он сам ставит остальное (GitHub CLI
   `gh`, uv, Node.js, движок агента) и задаёт вопросы (раздел 7). Вход в
   GitHub будет внутри установщика, на шаге 5.

**Когда ещё спросят пароль sudo.** Установщик сам проверяет права sudo на
шаге 1. Обычно пароль второй раз не нужен: sudo помнит его 15 минут в этом
окне терминала. Если с начала установки прошло больше 15 минут или вы
запускаете её повторно, снова может появиться `[sudo] password for user:`.
Это тот же пароль пользователя user.

**Результат**: в конце `[OK] Агент ответил на проверочный вопрос`,
`[OK] Установка завершена` и блок «Готово. Что дальше». Бот присылает в
Telegram «Установка завершена».
**Проверка**: `ls ~/projects/agent-second-brain` показывает `bootstrap.sh`, `setup.sh`, `vault`.
**Если ошибка**:

* `Could not get lock /var/lib/dpkg/lock`: сервер сам ставит обновления после создания. Подождите 5 минут и повторите команду.
* `Repository not found` или git спрашивает `Username for 'https://github.com'`: адрес в команде повреждён при копировании. Нажмите Ctrl+C и скопируйте команду заново целиком. Логин и пароль сюда не вводите.
* `Could not resolve host: github.com`: на сервере нет интернета или DNS. Подождите минуту и повторите команду.
* `destination path ... already exists`: программа уже скачана. Продолжайте командой повторного запуска ниже.
* Вход в GitHub на шаге 5 не завершился: выполните повторный запуск ниже, код действует 15 минут.

### Повторный запуск

Если установка прервалась (закрыли окно, ошибка, пропал интернет), войдите на
сервер (`ssh user@IP_СЕРВЕРА`) и выполните:

```bash
bash ~/projects/agent-second-brain/bootstrap.sh
```

Готовые шаги пропускаются. Уже введённые токены повторно не спрашиваются.
Память и ответы онбординга не перезаписываются.

## 7. Вопросы установщика

Установщик идёт по 14 шагам и показывает номер текущего. Вопросы:

| Вопрос | Что ответить |
|---|---|
| Пароль `[sudo]` | пароль пользователя user (если спросят; см. раздел 6) |
| Токен бота | токен из пункта 2.2. При вставке символы не видны, это нормально |
| Telegram ID | число из пункта 2.3 |
| Ключ Deepgram | ключ из пункта 2.4. Символы не видны |
| Часовой пояс | Enter, если предложен верный; иначе например `Europe/Moscow`, `Asia/Almaty` |
| Движок агента | `1` Codex или `2` Claude Code, по вашей подписке |
| Права агента | `1` полный доступ на выделенном сервере (рекомендуется) или `2` стандартный. Подробности в разделе 12 |
| Ночная уборка сервера | `1` включить (рекомендуется) или `2` нет. Что именно она делает — ниже в этом разделе |
| Имя приватного репозитория | Enter (будет `dbrain-vault`) |

**Вход в GitHub (шаг 5 «Вход в GitHub (для приватной копии памяти)»)**.
Нужен, чтобы установщик создал в вашем аккаунте приватный репозиторий
`dbrain-vault` и каждый день отправлял туда копию памяти. Программа при этом
не меняется и никуда не отправляется.

1. Вопрос `? Authenticate Git with your GitHub credentials? (Y/n)`: нажмите
   Enter (это значит «да»).
2. Появится `! First copy your one-time code: ABCD-1234` (у вас будет свой
   код) и `Press Enter to open https://github.com/login/device in your
   browser...`. Запишите код и нажмите Enter.
3. На компьютере или телефоне откройте
   [github.com/login/device](https://github.com/login/device), войдите в свой
   аккаунт GitHub, введите код, нажмите **Continue**, затем **Authorize**.
4. Браузер на сервере не нужен. Если терминал напишет, что не смог открыть
   браузер, это нормально: он ждёт, пока вы подтвердите вход на компьютере.
5. После подтверждения терминал сам продолжит: `✓ Authentication complete`,
   затем `[OK] GitHub готов`.

Если вы уже входили раньше (повторный запуск), шаг покажет
`[OK] GitHub уже подключён` без кода.

Во время проверки токенов бот пришлёт вам в Telegram сообщение «Проверка
связи». Если установщик пишет, что бот не может написать вам, откройте своего
бота в Telegram, нажмите **Start** и вернитесь в терминал.

**Вход в движок**:

* **Codex** покажет ссылку `https://auth.openai.com/codex/device` и код. Откройте ссылку на компьютере, войдите в ChatGPT, введите код. Код действует 15 минут.
* **Claude Code** откроется прямо в терминале. Выберите вход по подписке, откройте ссылку на компьютере, подтвердите, вставьте код в терминал. Когда появится поле ввода Claude, напечатайте `/exit` и нажмите Enter.

**Ночная уборка сервера (шаг 13).** Сервер со временем зарастает: забытые
окна терминала держат память, кэши и логи занимают диск. Если ответить `1`,
раз в сутки в 20:30 по вашему времени запускается уборка, а отчёт приходит
вам в Telegram.

Что она делает и чего не делает:

* закрывает окно терминала, только если оно **7 суток без активности**, к нему
  никто не подключён, в нём одно окно и пустое приглашение ввода. Рабочие
  сессии самого агента не трогаются никогда;
* удаляет только то, что восстанавливается само: старые файлы кэшей и
  временные папки, логи завершённых фоновых задач сжимает в архив;
* **не трогает** вашу память (`vault`), историю диалогов с агентом, файлы
  проектов и настройки.

Если у вас в терминале идёт долгая работа, которую нельзя закрывать, попросите
агента в этом окне: «защити эту сессию от уборки». Снять защиту — «убери
защиту». Проверить и запустить вручную можно так:

```bash
python3 ~/projects/agent-second-brain/scripts/server_cleanup.py run --dry-run
```

Передумали после установки: `1` или `2` спрашиваются снова при повторном
запуске установки, либо поменяйте `DBRAIN_CLEANUP=on|off` в
`~/projects/agent-second-brain/.env` и выполните
`bash ~/projects/agent-second-brain/upgrade.sh`.

**Проверка агента в конце.** На шаге 12 установщик задаёт агенту проверочный
вопрос и печатает «Осмотр» со строками ✅ и ❌. Установка считается
завершённой, только если агент ответил.

**Если ошибка**: установщик пишет `[X]`, причину и строку «Что сделать».
Выполните подсказку и запустите [повторный запуск](#повторный-запуск).
Частые случаи:

| Сообщение | Что сделать |
|---|---|
| `Вход в GitHub не завершён` | запустите установку снова и введите код на github.com/login/device в течение 15 минут |
| `Telegram не принял токен` | скопируйте токен из @BotFather целиком; ответьте `Y` и вставьте заново |
| `Бот ... не может написать вам` | откройте своего бота в Telegram, нажмите **Start**, вернитесь в терминал и нажмите Enter |
| `Deepgram не принял ключ` | создайте новый ключ в console.deepgram.com и вставьте его |
| `Вход в Codex не выполнен` | запустите установку снова и введите код на компьютере в течение 15 минут |
| `Сервисы запущены, но агент пока не отвечает` | если в осмотре строка `canary: ... нет входа в подписку`, выполните `dbrain login`, затем `dbrain doctor` (должно быть «Осмотр пройден») и запустите установку снова |

## 8. Проверка после установки

```bash

```

**Результат**: `bot: active`, `watchdog: active` и строка `мозг:`. Для Codex в

**Если ошибка**: `dbrain: command not found`. Выполните `source ~/.bashrc` и повторите.
Если сервисы не `active`, переходите к разделу 15.


**Результат**: `PRIVATE`. Любое другое значение означает, что память не будет

## 9. Знакомство с агентом (онбординг)

Отправьте боту:

```text
/onboarding
```

Агент проведёт вас через 8 шагов:

1. **Профиль**: как обращаться, часовой пояс, роль.
2. **Проекты и люди**: карта вашей работы.
3. **Цели**: на год, месяц и один главный результат недели.
4. **Стиль работы**: как отвечать, что можно делать самостоятельно.
5. **Сервисы**: какими инструментами пользуетесь, что подключать.
6. **Заметки**: импорт старых заметок, их разбор и раскладка по памяти.
7. **Проверка**: агент пересказывает, как понял вас, вы подтверждаете или поправляете.
8. **Возможности**: короткая памятка, что можно просить.

Перед каждым шагом агент объясняет, зачем спрашивает. Отвечать можно голосом
и своими словами. Каждый ответ сохраняется сразу.

**Прервать** можно в любой момент: напишите «стоп» или просто перестаньте
отвечать. **Продолжить**: снова `/onboarding`, агент начнёт с первого
неотвеченного вопроса.

**Заметки**. Агент подскажет, как выгрузить их из Apple Notes, Google Keep,
Notion или папки с файлами. Небольшие файлы можно прислать боту документом.
Оригиналы копируются в `inbox/raw-import/` и не изменяются. Сначала агент
показывает план разбора (что куда положить), раскладывает только после вашего
«да».

**Проверка результата**: в конце агент покажет профиль, память и цели. Этот
контекст он использует во всех следующих ответах.

**Как поправить позже**:

* скажите «запомни, что ...» или «обнови цели месяца: ...»;
* `/onboarding` и «вернёмся к целям» открывает любой шаг заново, остальные сохраняются;
* отредактируйте файлы в Obsidian (раздел 10): `MEMORY.md`, `goals/`, `personal/about.md`.

**Без Telegram** то же самое доступно в терминале сервера:

```bash
dbrain onboarding status
dbrain onboarding resume
```

## 10. Память в Obsidian на компьютере

Память живёт на сервере и каждый вечер отправляется в ваш приватный
репозиторий `dbrain-vault`. Чтобы читать её в Obsidian:

1. Установите [GitHub Desktop](https://desktop.github.com) и войдите в свой аккаунт.
2. **File → Clone repository** → выберите `dbrain-vault` → Clone.
3. Установите [Obsidian](https://obsidian.md), **Open folder as vault** → папка `dbrain-vault`.
4. Перед чтением нажимайте **Fetch origin → Pull** в GitHub Desktop, чтобы получить свежие изменения.

**Проверка**: в Obsidian видны `GUIDE.md`, `MEMORY.md`, папки `goals`, `daily`.

**Если правите файлы на компьютере**: после правок в GitHub Desktop нажмите
**Commit** и **Push**, затем попросите агента «подтяни мои правки из GitHub».
Одновременная правка одного файла на сервере и на компьютере может дать
конфликт; агент умеет его разрешить, если попросить.

## 11. Расписания и команды

Готовые расписания:

| Что | Когда |
|---|---|
| Обработка записей дня, отчёт в Telegram, резервная копия памяти | ежедневно 21:00 |
| Проверка здоровья агента | ежедневно 08:00 |
| Уборка сервера, если включена при установке | ежедневно 20:30 |

**Как агент ведёт диалог.** Это видно сразу и специально настраивать нечего:

* **Ничего не теряется.** Пока агент отвечает на одно сообщение, следующие
  встают в очередь и обрабатываются по порядку, даже если вы прислали их
  подряд. Бот подтверждает приём каждого.
* **Видно, что он занят.** Пока идёт длинный ответ, в чате обновляется
  карточка с ходом работы; когда ответ готов, карточка исчезает, а последним
  сообщением остаётся сам ответ.
* **Ответ не пропадает при перезапуске.** `dbrain restart` и обновление ждут,
  пока текущий ответ договорится (до 5 минут), и только потом перезапускают
  бота. Поэтому перезапуск иногда выглядит «зависшим» — это ожидание, а не
  сбой.
* **Если кажется, что всё замерло** — отправьте `/work`: он ответит даже
  тогда, когда агент занят, и скажет, сколько длится текущий ход и где
  затык.

Свои расписания создаются обычной просьбой:

* «Каждый будний день в 9:00 присылай план дня»;
* «Напомни завтра в 15:00 позвонить Анне»;
* «Каждое воскресенье в 18:00 делай обзор недели»;
* «Какие у меня расписания?», «Отмени утренний план».

Команды в Telegram:

| Команда | Что делает |
|---|---|
| `/start`, `/help` | справка |
| `/onboarding` | знакомство, продолжение с места остановки |
| `/process` | обработать записи дня прямо сейчас |
| `/status` | статус дня |
| `/work` | что агент делает прямо сейчас: идёт ли ответ, сколько уже длится, где застряло |
| `/resend` | прислать последний ответ ещё раз, если сообщение не дошло |
| `/new` | начать новый диалог (память в файлах сохраняется) |
| `/compact` | сжать контекст длинного диалога |
| `/relogin` | пересоздать сессию, если после `dbrain login` бот всё ещё просит вход |

Команды на сервере:

| Команда | Что делает |
|---|---|
| `dbrain status` | состояние сервисов |
| `dbrain doctor` | проверка с подсказками |
| `dbrain logs` | последние логи |
| `dbrain restart` | перезапуск |
| `dbrain repair` | сброс ошибок и перезапуск |
| `dbrain login` | повторный вход в Codex или Claude |
| `dbrain onboarding status` | прогресс онбординга |
| `dbrain permissions status` | текущие права агента |

Полная памятка лежит в памяти: файл `GUIDE.md`.

## 12. Права агента

Агент работает от пользователя `user` на выделенном сервере. Граница доступа:
этот сервер и этот пользователь. Токены хранятся в
`~/projects/agent-second-brain/.env` с доступом только для владельца.

| Профиль | Что может агент без вопросов |
|---|---|
| `max` (рекомендуется для выделенного сервера) | всё в своей папке и расписаниях, установка программ и настройка сервера через sudo без пароля |
| `standard` | всё в своей папке, памяти и расписаниях; системные команды (sudo) выполняете вы по его подсказке |

С движком Codex выбирайте `max`: в профиле `standard` Codex может записывать
только в папку памяти, поэтому создание расписаний и часть служебных команд
могут не сработать.

В обоих профилях агент **всегда спрашивает подтверждение** перед публикацией
чего-либо, платежами, необратимым удалением, выдачей доступа внешним сервисам
и отправкой сообщений третьим лицам.

Посмотреть и сменить профиль:

```bash
dbrain permissions status
dbrain permissions standard
dbrain permissions max
```

**Результат**: `[OK] Профиль прав: ...`. Затем отправьте боту `/new`, чтобы новый
диалог начался с новыми правами.

## 13. Дополнительные подключения

При установке подключаются только GitHub (копия памяти), Telegram и Deepgram.
**Готовых подключений к Google Drive, Google Calendar, Gmail, Notion и другим
сервисам в этой версии нет, мастера подключения тоже нет.** На онбординге
агент только составит список сервисов, которыми вы пользуетесь
(`personal/connections.md`).

Если захотите подключить сервис позже:

1. Спросите агента, например: «Хочу подключить Google Drive. Какие шаги и какие права понадобятся?»
2. Настройка идёт вручную, по шагам агента. Как она пройдёт, зависит от сервиса. Эта инструкция её не проверяла.
3. Пароли, токены и ключи вводите **только в терминале сервера**, никогда в чат.

**Если токен случайно отправлен в чат**: сразу отзовите его в сервисе, где он
выдан, и создайте новый.

## 14. Обновление

Когда вам сообщат о новой версии (вход в GitHub для этого не нужен,
программа скачивается из открытого репозитория):

```bash
git -C ~/projects/agent-second-brain pull --ff-only && bash ~/projects/agent-second-brain/upgrade.sh
```

**Результат**: в конце `Upgrade complete`. Если вместо этого
`Upgrade installed, but the health check failed`, исправьте первую строку ❌
выше (обычно `dbrain login`) и выполните `dbrain doctor`.
**Проверка**: `dbrain status` показывает `active`.
**Если ошибка**: `Not possible to fast-forward`. Вы или агент меняли файлы
программы. Выполните `git -C ~/projects/agent-second-brain status` и перешлите
вывод агенту или тому, кто помогает вам с установкой. Память (`vault`) и `.env` при
обновлении не затрагиваются.

## 15. Если что-то сломалось

| Симптом | Что сделать |
|---|---|
| Бот не отвечает | сначала `/work` в Telegram: он покажет, идёт ли ход. Если ход не идёт — `dbrain repair`, через минуту написать боту ещё раз; затем `dbrain doctor` |
| Ответ не дошёл, хотя агент отработал | `/resend` в Telegram |
| Бот пишет «Нужен вход в подписку ИИ» | `dbrain login` на сервере (ссылка и код на компьютере), затем написать боту снова; если всё ещё просит, `/relogin` |
| Голосовые не распознаются | `dbrain logs 100`; при ошибке Deepgram создайте новый ключ, замените `DEEPGRAM_API_KEY` в `.env` (`nano ~/projects/agent-second-brain/.env`, сохранить Ctrl+O, Enter, выйти Ctrl+X), затем `dbrain restart` |
| Сервер перезагрузился | ничего: сервисы стартуют сами. Проверка: `dbrain status` |
| Не приходит вечерний отчёт | `systemctl --user list-timers`; `journalctl --user -u dbrain-process -n 50` |
| Память не попадает в GitHub | `git -C ~/projects/agent-second-brain/vault push`; при ошибке входа `gh auth login -h github.com -p https -w` и `gh auth setup-git` |
| Всё сломалось, неясно почему | `dbrain doctor` и перешлите вывод агенту или тому, кто помогает вам с установкой |

**Сервер потерян или нужен новый**: пройдите разделы 3–6 на новом сервере. На
вопрос об имени репозитория памяти введите то же имя `dbrain-vault`:
установщик подключит существующий приватный репозиторий и восстановит из него
память (сообщение `[OK] Память восстановлена из dbrain-vault`).
Изменения, сделанные после последней вечерней копии, на старом сервере
остались и не восстановятся.

## 16. Безопасность и удаление

* Не пересылайте никому `.env`, токены и коды входа.
* Смена токена Telegram: в @BotFather `/revoke`, затем новый токен в `.env` (`TELEGRAM_BOT_TOKEN=`) и `dbrain restart`.
* Смена ключа Deepgram: удалите старый ключ в консоли Deepgram, создайте новый, замените `DEEPGRAM_API_KEY=` в `.env`, `dbrain restart`.
* Что уходит наружу: аудио голосовых в Deepgram для расшифровки; текст запросов выбранному ИИ (OpenAI для Codex, Anthropic для Claude Code); память в ваш приватный GitHub. Остальное остаётся на сервере.

**Удаление с сохранением памяти**. Сначала убедитесь, что память отправлена:

```bash
git -C ~/projects/agent-second-brain/vault push
```

**Результат**: `Everything up-to-date` или успешная отправка. Затем:

```bash
systemctl --user disable --now dbrain-bot.service dbrain-watchdog.service dbrain-process.timer dbrain-doctor.timer dbrain-delivery-watch.timer
```

```bash
rm -rf ~/projects/agent-second-brain ~/.dbrain
```

Приватный репозиторий `dbrain-vault` на GitHub остаётся. Удаляйте его отдельно
только если действительно хотите стереть память.
