# Обязательные правила обработки

Контекст и предпочтения владельца: `references/about.md` (откуда их брать).

## Правило 1: пропускать обработанное

```
Если в записи есть `<!-- ✓ processed` → ПОЛНОСТЬЮ ПРОПУСТИТЬ
```

Маркер ищи сразу после заголовка `## HH:MM` и в теле записи.

## Правило 2: у каждой задачи есть срок

Никогда не создавай задачу без `due`. Даты считай в часовом поясе владельца
(`personal/about.md`), записывай как `YYYY-MM-DD`.

| В тексте | due |
|----------|-----|
| сегодня | текущая дата |
| завтра | +1 день |
| в пятницу | ближайшая пятница |
| на этой неделе | пятница этой недели |
| 15 апреля | YYYY-04-15 (ближайшее будущее) |
| НЕ УКАЗАНО | +3 дня |

## Правило 3: проверять дубликаты

Перед созданием задачи:

1. Найди открытые `- [ ]` с теми же ключевыми словами в `daily/` за 14 дней
   и в `projects/*/status.md`.
2. Если похожая есть, **не создавай** новую.
3. Пометь запись: `<!-- ✓ processed: task (duplicate) -->`.

## Правило 4: учитывать загрузку

Перед созданием задач:

1. Посчитай открытые задачи со сроками на 7 дней вперёд.
2. Если на целевой день уже 3+ задачи, сдвинь срок на ближайший менее
   загруженный день.
3. Задачи p1 и задачи с явной датой от владельца не сдвигай.

## Правило 5: помечать после обработки

После КАЖДОЙ обработанной записи добавь маркер:

```markdown
<!-- ✓ processed: {category} -->
```

Для задач:
```markdown
<!-- ✓ processed: task → {кратко задача} {priority} {due} -->
```

## Правило 6: фильтры решений

Если владелец описал свои критерии в `MEMORY.md`, применяй их. Иначе спроси:
- Двигает ли это к цели недели, месяца или года?
- Это масштабируется или повторяется (стоит сделать системно)?
- Это можно поручить или автоматизировать?
- Есть ли внешний срок или обязательство перед другим человеком?

Два и больше «да» → повысь приоритет на ступень (не выше p2 без жёсткого срока).

## Правило 7: избегать анти-паттернов

Никогда не создавай:
- абстрактные задачи без следующего шага («Подумать о…»);
- хаотичные списки без приоритетов;
- повторы без синтеза;
- теорию без применения.

## Правило 8: не выходить за рамки обработки

- Обработка только раскладывает записи владельца. Не отправляй сообщения
  третьим лицам, не публикуй, не плати, не удаляй файлы.
- Не создавай и не меняй расписания без явной просьбы в записи; если просьба
  есть («каждый понедельник напоминай…»), создай через скилл `cron` и покажи
  в отчёте. Внутри запуска `[CRON JOB …]` расписания не трогай вообще.
- Секреты (пароли, токены, номера карт), попавшие в записи, не переноси в
  заметки и память; в отчёте посоветуй удалить их из daily и перевыпустить.

- [ ] Применены фильтры решений
- [ ] Нет анти-паттернов
- [ ] MOC обновлены
- [ ] Журнал действий записан в daily
- [ ] handoff.md и (если нужно) MEMORY.md обновлены
