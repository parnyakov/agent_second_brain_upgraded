# Контекст владельца

Этот файл не содержит данных о владельце. Он описывает, откуда их брать.
Всё личное живёт в vault и заполняется онбордингом и разговорами.

## Источники

| Что нужно | Где взять | Кто заполняет |
|-----------|-----------|---------------|
| Имя, роль, часовой пояс, язык, текущий этап | `personal/about.md` | Онбординг, раздел «Профиль» |
| Активные проекты и направления | `projects/_index.md` → «Активные проекты» | Онбординг, раздел «Проекты и люди» |
| Ключевые люди и их роли | `projects/_index.md` → «Люди», карточки `type: contact` | Онбординг, затем агент по подтверждению |
| Личная зона ответственности | `projects/_index.md` → «Моя ответственность» | Онбординг |
| Цели 3 года, год, месяц, неделя | `goals/*.md` | Онбординг, затем владелец и агент |
| Стиль ответов, границы самостоятельности, запреты | `MEMORY.md` | Онбординг, раздел «Стиль работы» |
| Устойчивые решения и предпочтения | `MEMORY.md` | Агент по подтверждению владельца |
| Сервисы и план подключений | `personal/connections.md` | Онбординг, раздел «Сервисы» |
| Текущее состояние проекта | `projects/{slug}/status.md` | Агент при обработке |

## Словарь проектов

Перед классификацией собери словарь:

1. Строки раздела «Активные проекты» в `projects/_index.md`: каждая строка
   это название проекта и, возможно, короткая пометка.
2. Существующие папки `projects/*/` (slug папки + заголовок `status.md`).
3. Для каждого проекта: название, slug, ключевые слова (название, синонимы,
   имена людей, связанных с проектом).

Пример того, как может выглядеть заполненный индекс (не данные владельца):

```markdown
## Активные проекты

Проект А: запуск нового продукта для корпоративных клиентов
Проект Б: перестройка процесса найма в отделе

## Люди

Анна (партнёр): финансы и договоры по Проекту А
Иван (руководитель отдела): согласует бюджеты
```

Из него получается словарь:

| Проект | slug | Ключевые слова |
|--------|------|----------------|
| Проект А | `proekt-a` | «Проект А», запуск, корпоративные клиенты, Анна |
| Проект Б | `proekt-b` | «Проект Б», найм, вакансии, собеседования |

Если папки проекта ещё нет, slug делай латиницей в нижнем регистре через
дефис. Папку создавай только при первой реальной записи по проекту.

## Фильтры решений

Если в `MEMORY.md` владелец описал свои критерии («что важно», «от чего
отказываюсь», «как расставляю приоритеты»), применяй их при выборе приоритета.
Если критериев нет, используй общие вопросы из `references/rules.md`.

## Когда контекста не хватает

- Файлов нет (онбординг не пройден): обрабатывай по общим признакам и
  добавь в отчёт напоминание продолжить /onboarding (не чаще раза в день).
- Упомянут неизвестный проект или человек: не выдумывай, свяжи позже; в
  отчёте спроси владельца, стоит ли его добавить.
- Противоречие между `MEMORY.md` и свежей записью владельца: доверяй свежей
  записи, а изменение памяти покажи в отчёте.
