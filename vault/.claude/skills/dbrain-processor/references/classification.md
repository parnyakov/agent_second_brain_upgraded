# Классификация записей

Классификация строится вокруг доменов: проектов владельца и областей жизни.
Список проектов не зашит в этот файл: его даёт словарь из
`references/about.md` (`projects/_index.md` + папки `projects/*/`).

## Домены

### Проекты владельца
Каждый активный проект из словаря. Ключевые слова: название, синонимы,
связанные люди, характерные термины.

**→ Файлы:** `projects/{slug}/status.md` и тематические файлы в
`projects/{slug}/` (если владелец их завёл).

### Личное
Здоровье, семья, деньги, обучение, книги, путешествия, спорт и всё, что вне
рабочих проектов.

**→ Файлы:** `personal/` (подпапки по темам, если владелец их завёл) или
`thoughts/reflections/`.

Пример маршрутизации (заводи подпапку только когда по теме накопилось
несколько записей, и сообщи об этом в отчёте):

| Тема, ключевые слова | Путь |
|----------------------|------|
| работа, карьера, собеседование, оффер | `personal/career/` |
| семья, дети, родители | `personal/family/` |
| деньги, бюджет, инвестиции, налоги (личные) | `personal/money/` |
| курс, книга, обучение | `personal/learning/` |
| тренировка, бег, здоровье | `personal/health/` |
| поездка, отпуск | `personal/travel/` |

### Сам агент
Настройка агента: скиллы, правила, расписания, подключения.

**→** `thoughts/projects/` (или задача, если есть конкретное действие).

## Дерево решений

```
Запись содержит...
│
├─ Жёсткий срок или срочность? ─────────────────> TASK (p1)
│  (сегодня, завтра, дедлайн, срочно, не забыть)
│
├─ Совпадает с ONE Big Thing недели? ───────────> TASK (p2)
│
├─ Совпадает с приоритетом месяца? ─────────────> TASK (p2)
│
├─ Относится к проекту из словаря,
│  но не приоритет сейчас? ─────────────────────> TASK (p3) + [[project]] ссылка
│  или обновление status.md проекта
│
├─ Про настройку самого агента? ────────────────> PROJECT → thoughts/projects/
│
├─ Новое знание, приём, вывод из книги/курса? ──> LEARNING
│
├─ Личный инсайт (здоровье, семья, состояние)? ─> REFLECTION
│
├─ Идея без срока? ─────────────────────────────> IDEA
│
└─ Операционное, вне целей? ────────────────────> TASK (p4)
```

## Упоминание проекта

```
Запись упоминает проект из словаря?
├─ + новость ("запустили", "сделали", "перенесли")? → строка в «История»
│   projects/{slug}/status.md (или в тематическом файле проекта)
├─ + существенная смена состояния проекта? → копия status.md в
│   projects/{slug}/archive/YYYY-MM-DD.md, затем новая версия status.md
├─ + срок или срочность? → TASK (p1-p2) + [[project]] ссылка
└─ просто упоминание? → только [[project]] ссылка
```

### Правило архивации status.md

Перед перезаписью `projects/{slug}/status.md`:
1. Скопировать текущее содержимое в `projects/{slug}/archive/YYYY-MM-DD.md`.
2. Только потом записать новую версию.

Ничего не перезаписывается без сохранённой предыдущей версии.

## Фильтры решений

Перед сохранением спроси:
- Двигает ли это к цели года или месяца?
- Это конкретный следующий шаг, а не абстрактный результат?
- Это повторится или разово?

Если явно двигает к ONE Big Thing или приоритету месяца, повысь приоритет до p2.
Критерии владельца из `MEMORY.md` важнее этих общих вопросов.

---

## Фото и документы

Для `[photo]` и `[document]`:
1. Посмотри содержимое (vision для изображений).
2. Определи домен по содержимому (например, скриншот переписки по Проекту А,
   фото чека, страница договора).
3. Добавь краткое описание в daily; при необходимости обнови файл проекта.
4. Не переписывай в vault персональные данные третьих лиц и платёжные
   реквизиты, если владелец прямо не попросил.

## Куда что сохраняется

| Класс | Назначение | Приоритет |
|-------|------------|-----------|
| task (жёсткий срок) | чек-лист в daily / проекте | p1 |
| task (фокус недели или месяца) | чек-лист в daily / проекте | p2 |
| task (проект, не срочно) | чек-лист + [[project]] ссылка | p3 |
| task (операционное) | чек-лист в daily | p4 |
| новость проекта | `projects/{slug}/status.md` | - |
| idea | `thoughts/ideas/` | - |
| reflection | `thoughts/reflections/` | - |
| learning | `thoughts/learnings/` | - |
| про агента | `thoughts/projects/` | - |

## Имена файлов

```
thoughts/{category}/YYYY-MM-DD-short-title.md
```

Примеры:
```
thoughts/ideas/2026-03-12-client-onboarding-checklist.md
thoughts/reflections/2026-03-12-meetings-drain-mornings.md
thoughts/learnings/2026-03-12-weekly-review-calendar-first.md
```

## Структура заметки

```markdown
---
type: note
description: >-
  Одна строка для поиска: суть заметки
tags: [tag1, tag2]
status: active
created: YYYY-MM-DD
source: daily/YYYY-MM-DD.md
domain: {Проект из словаря|Личное|Агент}
related: []
---

## Контекст
[Что привело к мысли]

## Суть
[Ключевая идея]

## Что это значит
[Для какого проекта или области и почему важно]

## Следующий шаг
[Конкретное действие, не абстракция]
```

---

## Анти-паттерны

Не создавай:
- Рассуждения без следующего шага
- Теорию без применения к конкретному проекту или области
- Повторы без синтеза (объединяй похожие заметки)
- Хаотичные списки без приоритетов
- Задачи «подумать о…» (конкретизируй действие)

---

## Обновление MOC

После создания заметки добавь ссылку в `MOC/MOC-{category}.md`
(`MOC-ideas`, `MOC-reflections`, `MOC-learnings`, `MOC-projects`), группируя
по домену:

```markdown
## Проект А
- [[2026-03-12-client-onboarding-checklist]] - чек-лист подключения клиента

## Агент
- [[2026-03-12-evening-report-shorter]] - сократить вечерний отчёт
```
